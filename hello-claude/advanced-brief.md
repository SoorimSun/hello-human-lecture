# 심화 실습: 모임 안내 페이지를 준비 도구로 확장하기

## 출발점과 목적
- 기본 실습에서 index.html 한 장을 만들고 내용을 확인했습니다.
- 기존 모임 안내를 읽는 사람이 준비물을 빠뜨리지 않게 돕고 싶습니다.
- Wayfinder로 범위를 정하고, Superpowers로 설계·구현·검증하는 과정을 연습합니다.
- 이 문서는 학습용 입력입니다. 실제 개인 정보나 참가자 자료는 사용하지 않습니다.

## 먼저 결정할 질문
1. 첫 기능은 준비물 확인, 일정 저장, 참가 신청 중 어떤 문제에 집중할까요?
2. 준비 상태는 페이지를 보는 동안만 필요할까요, 다음 방문에도 남아야 할까요?
3. 무엇이 실제로 동작하면 첫 기능을 완료했다고 할 수 있을까요?

Wayfinder는 큰 일의 미결정 질문을 정리하는 도구입니다.
이 작업이 이미 명확하고 작다면 지도를 억지로 만들지 않습니다.
지도 대신 결정 요약을 남기고 Superpowers에 넘겨도 됩니다.
지도가 필요하면 로컬 Markdown 트래커를 사용합니다.
지도 작성과 개별 결정 해결은 세션을 나눠 진행합니다.

## 가이드에서 선택해 볼 범위
아래는 선택 예시이며, 사용자가 실제로 답한 내용을 우선합니다.
- 노트북, 함께 이야기할 아이디어: 체크박스 2개
- 준비한 항목 수: 0/2, 1/2, 2/2 표시
- 전체 초기화 버튼
- 새로고침하면 모두 해제; 저장소나 서버에 상태를 보관하지 않음
- 로그인, 참가 신청, 알림, 기기 간 동기화는 이번 범위에서 제외

## 이 범위를 선택했을 때의 완료 조건
- 처음 열면 두 항목은 해제되어 있고 0/2가 보입니다.
- 하나를 선택하면 1/2, 둘을 선택하면 2/2입니다.
- 선택을 해제하면 숫자가 즉시 줄어듭니다.
- 전체 초기화 버튼은 체크와 표시 숫자를 함께 초기화합니다.
- 새로고침하면 다시 0/2입니다.
- 키보드 Tab으로 이동하고 Space로 체크할 수 있습니다.
- 휴대폰 390px와 데스크톱 폭에서 내용이 잘리지 않습니다.
- 현재 index.html의 날짜·시간·장소·신청 안내는 유지합니다.

## 설계와 구현
- 학습을 위해 짧은 설계 문서와 구현 계획을 로컬 파일로 남깁니다.
  작은 변경에 언제나 이 문서들이 필요하다는 뜻은 아닙니다.
- 사용자가 실제 설계와 구현 계획을 읽고 승인한 뒤 구현합니다.
- 별도 기능 브랜치와 격리된 작업 폴더를 사용합니다.
- index.html 안에 CSS와 JavaScript를 두고 정적 HTML 한 장을 유지합니다.
- 사이트가 실행될 때 필요한 외부 패키지, 프레임워크, 서버는 추가하지 않습니다.
- 로컬 개발용 설계·설정·테스트 파일은 추가할 수 있습니다.
- 테스트에는 Playwright Test를 개발용으로 사용합니다.
- 테스트 환경에는 지원되는 Node.js와 npm, Chromium이 필요합니다.
- 테스트용 서버는 127.0.0.1에서만 실행하고 별도 빌드는 도입하지 않습니다.
- package.json에 npm test로 전체 테스트를 실행할 수 있게 구성합니다.
- 기능이 없어서 실패하는 테스트를 실제 실행한 후 최소 구현으로 통과시킵니다.
- 설치·서버 오류는 기능의 실패를 확인한 것으로 간주하지 않습니다.
- 최종 검증에는 자동 테스트, 화면 확인, 기존 내용 유지 확인을 포함합니다.
- 실행 명령과 결과, 미검증 항목을 구분해 보고합니다.

## 공개 범위와 작업 기록
- 별도 요청 전에는 커밋·푸시·병합하지 않습니다.
- 이슈·결정·설계는 로컬에 기록하며 외부 이슈를 만들지 않습니다.
- 나중에 배포할 파일은 검증한 index.html과 .nojekyll입니다.
- 기능 브랜치를 통째로 공개하지 않고 사이트 파일만 배포 브랜치에 반영합니다.
- advanced-brief.md, CLAUDE.md, AGENTS.md, 로컬 지도·설계·설정·테스트,
  node_modules, 테스트 결과, 인증 정보는 이번 공개 커밋에서 제외합니다.
- 원격 저장소·브랜치·기존 변경을 확인하고 강제 푸시나 덮어쓰기를 하지 않습니다.
